## Комплексна інфраструктурна система "JIDAI"

Програмно-апаратний комплекс для управління власною інфраструктурою, хостингу веб-сервісів та агрегації телеметрії пристроїв розумного будинку (IoT). 

Система побудована на мікросервісній архітектурі з використанням технології контейнеризації Docker та централізованої шини обміну даними на базі протоколу MQTT. Ключовою особливістю проєкту є поєднання класичного веб-хостингу (з підтримкою Single Sign-On авторизації) та асинхронних інтеграційних мостів для збору персональної статистики з платформ Telegram, Anki та Last.fm.

### Архітектура та компоненти

Застосунок розділено на два логічні рівні: серверне ядро (Server) та рівень кінцевих пристроїв (Devices).

#### 1. Серверне ядро (Docker Compose)
- **Nginx & Authelia:** Забезпечення маршрутизації (Reverse Proxy) та захисту сервісів за допомогою двофакторної автентифікації (2FA/TOTP).
- **Eclipse Mosquitto:** Центральний MQTT-брокер, що виступає єдиною шиною подій для IoT-пристроїв та програмних скриптів.
- **Node-RED:** Візуальне середовище для налаштування правил автоматизації та обробки вхідних даних.
- **СУБД PostgreSQL:** Основне сховище даних для розгорнутих застосунків.
- **Jetty (Servlets):** Легковагий контейнер сервлетів для виконання Java-застосунків (Spring).
- **Vikunja:** Self-hosted система управління завданнями та продуктивністю.

#### 2. Інтеграційні мости (Python Asynchronous Workers)
Пакет скриптів, розгорнутих в окремому контейнері, що забезпечують двосторонній зв'язок між зовнішніми API та внутрішньою MQTT-шиною:
- `tg_bridge.py`: Використовує Telethon для моніторингу статусу користувача та пересилки повідомлень з/в MQTT.
- `anki_bridge.py`: Реалізує кастомний бінарний парсер Protobuf для збору статистики карток з AnkiWeb.
- `spotinfo_bridge.py`: Отримує дані про поточний трек з Last.fm та динамічно вираховує домінантний колір обкладинки альбому за допомогою ColorThief.

#### 3. Апаратна частина (IoT)
Програмне забезпечення для мікроконтролерів (написане з використанням Arduino core для ESP32/ESP8266):
- **ESP32 Main Base:** Центральний хаб з підтримкою BLE, зчитуванням показників з датчиків (SHT20, фоторезистор, радар), прийомом ІЧ-сигналів та керуванням реле. Взаємодіє з MQTT-брокером через апаратний міст на базі ESP-01.
- **Human Radar (ESP8266):** Автономний модуль детекції руху, оптимізований для роботи від батареї (використовує режим Deep Sleep).

### Розгортання системи

Для успішного запуску комплексу необхідна наявність встановлених `docker` та `docker-compose` на цільовій машині (Linux-сервер).

1. **Клонування репозиторію:**
```bash
git clone [https://github.com/AndriyKramar2288/jidai.git](https://github.com/AndriyKramar2288/jidai.git)
cd jidai
```

**Конфігурація середовища:**

Система використовує підхід "Infrastructure as Code", приховуючи конфіденційні дані. Необхідно створити реальні конфігураційні файли на основі наданих шаблонів:

- Скопіюйте `.env.example` у `.env` та заповніть паролі баз даних, API-ключі (Telegram, Last.fm) та токени.
- Скопіюйте `server/authelia/configuration.example.yml` у `configuration.yml` та вкажіть ваш цільовий домен.
- Згенеруйте власні хеші паролів для `users_database.yml`.

2. **Запуск контейнерів:**
```bash
cd server
docker-compose up -d --build
```
3. **Прошивка мікроконтролерів:**
Для кожного пристрою в директорії `devices/` створіть файл `secrets.h` на основі `secrets.example.h`, вказавши облікові дані вашої локальної Wi-Fi мережі та параметри доступу до розгорнутого MQTT-брокера. Прошивка здійснюється через Arduino IDE або PlatformIO.

Документація API (AsyncAPI)
Опис структури топіків, форматів JSON-повідомлень (Payload) та контрактів взаємодії між мікросервісами та мікроконтролерами стандартизовано за специфікацією AsyncAPI.

Повна документація доступна у форматі HTML (генерація через @asyncapi/web-component) та розгортається автоматично за адресою `https://docs.[ваш-домен]`. Вихідний файл конфігурації знаходиться за шляхом `server/docs/asyncapi.yaml`.
